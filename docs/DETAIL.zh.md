# 工作记忆

把你和 DSH 一起做过的工作编成一份索引。每条记录是一个**指针**——会话 id、序列区间、一句话标题、产物路径——不是摘要。长对话被压缩之后，原始事件仍然留在磁盘上，这个插件负责把原文原样取回来。

## 用起来是什么样

- **三个工具。** `memory_search` 按描述、文件名或关键词找过去的工作；`memory_open` 按序列区间回放当时那段对话，包括被压缩遮蔽的部分；`memory_write` 手动记一条决定。
- **自动捕获。** 每轮结束，只要像一次真实工作（提问有实质内容，或者写了文件），就落一条索引，并按关键词判定主题。
- **按需注入。** 每步会拿你刚说的话去检索，命中就在运行时上下文里加最多三行指针；没命中就什么都不加。运行时不调用模型。
- **网页面板。** 打开 `http://127.0.0.1:8282/work-memory/`，可以搜索、展开原文、改标题、归档。

## 第一次使用

账本初始是空的，从已有历史建起来：

```bash
node cli/bootstrap.js --dry-run          # 先看会扫什么
node cli/bootstrap.js --all              # 扫描、导入、归块、建索引（需要模型 key）
node cli/bootstrap.js --all --skip-llm   # 只跑不需要模型的步骤
```

`--max-sessions N` 限制让模型归块的会话数，这是主要成本。每个阶段都能重跑，已完成的会话自动跳过。

如果本机还装着别的编程 agent（ZCode、Hermes、WorkBuddy），bootstrap 会把它的历史一起导入同一份账本，`memory_open` 按来源前缀分派。

## 环境要求

- Node 22.19 以上（`node:sqlite` 和 `zstd` 都是内置的）。
- 只有离线归块需要模型：一个 OpenAI 兼容的 chat 端点，用 `DSH_WM_LLM_BASE_URL`、`DSH_WM_LLM_MODEL`、`DSH_WM_LLM_API_KEY` 配置。不配也能用，只是没法批量归块。

## 数据在哪

```
<DSH_HOME>/work-memory/hooks.jsonl   账本（仅追加）
<DSH_HOME>/work-memory/topics.json   可选的主题定义
```

不往你的工作区写任何东西。每次写入加锁、留备份，旧备份自动轮转。

## 已知限制

- 检索是字面的（中文二元组 + 拉丁词），同义词靠离线别名表兜，不走向量。
- 自动条目的标题是提问首句；让模型归块过的条目标题更好。
- 跨 agent 回放依赖对方的数据库结构。
- 面板是 host 侧代码，装完要重启一次 DSH。
